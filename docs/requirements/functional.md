**版本**: 1.0

**作者**: 需求分析助手 (Requirements Analyst AI)

## 1. 饮食模块 (DIET)

| ID | EARS 需求描述 | 实现逻辑 / 伪代码 |
| :--- | :--- | :--- |
| FR-DIET-01 | **当**用户提供自然语言输入（如“中午吃了300g番茄炒鸡蛋”）时，**系统应**调用 AI 服务解析食材和数量。 | `parse(text) -> {item: '番茄', qty: '150g'}, {item: '鸡蛋', qty: '150g'}` |
| FR-DIET-02 | **系统应**根据用户当前的基本信息（年龄、身高、体重、性别）每日计算个性化的 BMR/TDEE。 | `BMR = MifflinStJeor(user.age, user.weight, user.height, user.gender)` |
| FR-DIET-03 | **系统应**通过从“当日目标 (TDEE)”中减去“当日已摄入”来识别营养缺口。 | `Gap = Goal - Sum(ConsumedItems.nutrients)` |
| FR-DIET-04 | **若**某种关键营养素（如蛋白质）低于目标的 80%，**系统应**推荐特定食物（如鸡胸肉、牛肉）。 | `if (蛋白质 < 目标 * 0.8) recommend(['鸡胸肉', '牛肉'])` |
| FR-DIET-05 | **在**提供图片输入的情况下，**系统应**通过具备视觉能力的 AI 模型识别食物内容。 | `analyzeImage(file) -> List<食物项>` |

## 2. 运动模块 (WORK)

| ID | EARS 需求描述 | 实现逻辑 / 伪代码 |
| :--- | :--- | :--- |
| FR-WORK-01 | **系统应**使用 7 天/14 天滚动窗口生成运动趋势分析图表。 | `plot(user.exerciseHistory.last(14days))` |
| FR-WORK-02 | **当**最近 14 天的运动数据呈现持续上升趋势时，**系统应**触发“夸奖”反馈通知。 | `if (趋势斜率 > 0) notify("做得太棒了！")` |
| FR-WORK-03 | **若**平均运动时长较前一周下降超过 50%，**系统应**触发“警示”提醒。 | `if (近期均值 < 前期均值 * 0.5) notify("警惕体质下降！")` |
| FR-WORK-04 | **当**处于“运动会话”期间，**系统应**维护一个计时器，并根据计划中设定的“休息时长”在“运动中”和“休息”状态间切换。 | `状态机: WORK -> 计时结束 -> REST -> 计时结束 -> WORK` |

## 3. 睡眠模块 (SLEEP)

| ID | EARS 需求描述 | 实现逻辑 / 伪代码 |
| :--- | :--- | :--- |
| FR-SLEEP-01| **系统应**在记录的睡眠时长连续性 > 90% 时，将睡眠质量评定为“好”。 | `质量 = 连续时长 / 总时长 > 0.9 ? 好 : 差` |
| FR-SLEEP-02| **当**睡眠质量为“差”时，**系统应**生成 3 条可操作的调整建议（如“规范作息时间”）。 | `if (差) suggest(['固定入睡窗口', '戒断咖啡因', '清晨锻炼'])` |

## 4. 用户与社交模块 (SOCIAL)

| ID | EARS 需求描述 | 实现逻辑 / 伪代码 |
| :--- | :--- | :--- |
| FR-SOCIAL-01| **系统应**强制执行 1 个账号对应 1 个用户的映射关系。 | `User.id == Device.currentUserId` |
| FR-SOCIAL-02| **当**用户收到好友动态时，**应**能够直接针对该动态 ID 发布文字评论。 | `postComment(momentId, text)` |
| FR-SOCIAL-03| **系统应**支持在聊天界面中异步交付文字和图片消息。 | `Socket.send({type: '图片', payload: blob})` |
